# Shos.AICodingArticle

このリポジトリは、AIコーディングに関する資料収集、論点整理、記事執筆計画、記事ドラフト、比較レポートを管理するための作業リポジトリです。

アプリケーションコードや実行可能なソフトウェアを管理するリポジトリではありません。主な成果物は、日本語のMarkdown文書として作成された調査メモ、執筆計画、記事案、比較・レビュー結果です。初めて見る人は、まず `Plans` と `Data` で記事の前提を確認し、次に `Outputs` でドラフトと比較結果を追うと、作業の流れを把握しやすくなります。

## リポジトリの目的

このリポジトリでは、AIコーディングを「速くコードを書く技術」ではなく、「仕様・検証・責任を設計する組織能力」として捉える記事を作成しています。

扱っている主な論点は、Vibe Codingの限界、認知負債、理解負債、意図負債、AI生成コードのレビューとQA、仕様駆動開発、AI-DLC、エージェントの権限管理、若手育成における説明責任などです。

## フォルダー構成

| パス | 役割 |
| :--- | :--- |
| `Data` | 参照資料、資料まとめ、補助的な分析文書、リンク集を置く場所です。 |
| `Data/文字起こし` | AIコーディング関連テーマの文字起こし結果を置く場所です。記事の論点補強や別観点の素材として参照します。 |

| `Plans` | 記事執筆計画を置く場所です。テーマ、読者、構成、執筆ステップ、参照資料の扱いを確認できます。 |
| `Outputs` | 記事ドラフト、比較レポート、レビュー結果などの出力成果物を置く場所です。 |
| `.github/prompts` | 資料まとめ、執筆計画、記事執筆に使う再利用可能なプロンプトを置く場所です。 |

## 基本的な作業フロー

このリポジトリの作業は、次の流れで進められています。

1. `Data/[Link] AIコーディング` に参照資料のリンクを集める。
2. `.github/prompts/AIコーディング資料まとめ作成.prompt.md` を使い、資料群を横断したまとめを作成する。
3. `.github/prompts/AIコーディング記事執筆計画作成.prompt.md` を使い、記事のテーマ、読者、構成、執筆ステップを計画する。
4. `.github/prompts/AIコーディング記事執筆.prompt.md` を使い、`Plans` と `Data` の内容をもとに記事ドラフトを作成する。
5. 複数ドラフトを比較し、読みやすさ、実務性、根拠資料の追跡性、Markdown品質を確認する。
6. 比較レポートの採用方針に基づき、公開稿候補を改善する。

この流れを再利用する場合は、まず参照資料のリンク集を更新し、資料まとめ、執筆計画、記事執筆、比較の順に進めると、成果物の前提と判断理由を残しやすくなります。

## プロンプトの使い方

`.github/prompts` には、作業工程ごとのプロンプトが用意されています。

| プロンプト | 用途 |
| :--- | :--- |
| `AIコーディング資料まとめ作成.prompt.md` | 複数の参照資料を横断し、共通テーマ、課題、解決策、参照資料の扱いをまとめるためのプロンプトです。 |
| `AIコーディング記事執筆計画作成.prompt.md` | 記事のテーマ、想定読者、アウトライン、執筆ステップ、品質ゲートを作るためのプロンプトです。 |
| `AIコーディング記事執筆.prompt.md` | 既存の計画書と資料まとめをもとに、QiitaやZenn向けの記事ドラフトを作るためのプロンプトです。 |

プロンプトを使うときは、出力先フォルダーと既存ファイルの扱いを確認してください。既存ドラフトを上書きせず、新しいMarkdownファイルとして保存する前提のプロンプトがあります。

## Markdown品質ルール

記事やレポートを追加・更新するときは、次の点を確認してください。

- URLは裸URLのまま本文へ置かず、Markdownリンク形式で記述する。
- 「記事化する際」「本文化する際」「要修正」など、作業途中のメモに見える表現を公開候補へ残さない。
- 資料番号を使う場合は、本文中の番号と末尾の参照資料表が対応していることを確認する。
- `資料[1]` のような表記が未定義の参照リンクとして解釈されないよう、必要に応じて `資料1` のような自然文表記にする。
- 見出し、表、リンクが崩れていないかMarkdown診断を実行する。
- 定量値や調査結果は、調査条件が確認できない場合に断定的な横比較を避ける。

比較レポートには、既存ドラフトに対してMarkdown診断や裸URL、作業メモ表現、参照番号の確認を行った記録があります。新しい成果物を作る場合も、同じ観点で確認してください。

## 日本語ファイルを扱うときの注意

このリポジトリには、日本語のファイル名と日本語本文を含むMarkdownファイルが多く含まれています。WindowsやPowerShellで内容を確認・加工する場合は、文字コードに注意してください。

Windows PowerShell 5.1では、`Get-Content -Raw` でUTF-8の日本語ファイルを読むと文字化けする場合があります。機械的に整形・確認する場合は、UTF-8を明示して読み込む方法を使ってください。

```powershell
[System.IO.File]::ReadAllText("Data/2026-05-19-AIコーディング資料まとめ.md", [System.Text.Encoding]::UTF8)
```

ファイル名に日本語、スペース、角括弧を含むパスがあります。スクリプトやコマンドで扱う場合は、パスを引用符で囲んでください。

## 今後の作業候補

このリポジトリを引き継ぐ場合は、まず公開稿として採用する記事を明示すると、後から参照しやすくなります。比較レポートでは記事2と記事4が採用候補として評価されているため、記事5を含めて内容を確認し、必要なら統合版を `Outputs` に新規ファイルとして作成してください。

また、記事ドラフトの主要参照資料表と `Data/[Link] AIコーディング/[Link] AIコーディング.md` の番号対応を必要に応じて再確認すると、公開時の根拠追跡性を保ちやすくなります。文字起こしファイルは、既存記事の主張を補強する素材として使えますが、公開稿へ反映する場合は、本文中で資料まとめや主要参照資料との関係を整理してください。
